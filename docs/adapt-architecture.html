Full NameAutomated Data-driven Playwright Testing
Built ByDeepTree (deeptree.in)
PurposeA scalable, plug-and-play E2E test automation platform. One framework repo tests any number of web applications. No duplication of infrastructure across projects.
Test FrameworkPlaywright (TypeScript) — industry standard, native TS, parallel execution, built-in screenshots on failure
Data SourceExcel workbook per project — test cases, run control flags, user roles, and result history all in one file
Selector HealingThree heal scripts (heal:selectors, heal:actions, heal:dialogs) auto-fix broken selectors by inspecting the live app
Report FormatPrism — DeepTree's Playwright-style dark/light HTML design system (playwright-theme.css + html-builder.mjs)
First ProjectHappyQ — 53/56 tests passing, 5 roles, 40+ screens, 14 dialogs mapped
Problem & Solution
ProblemWithout ADAPTWith ADAPT
Starting a new project's test suite Set up Playwright, write config, build auth, design Excel schema — hours of boilerplate npm run new:project -- --name myapp --src D:\myapp — scaffolds everything in seconds
Selector guesses from source code are wrong Run tests, read error, open app, find real text, fix manually — repeated for every page npm run heal:selectors -- --project myapp — auto-heals all headings from live DOM
Adding a second app to automate Copy the entire test project, duplicate infrastructure, maintain two repos Add projects/myapp/ folder — all infrastructure shared, nothing duplicated
Non-developers need to control test runs Edit TypeScript files — requires dev knowledge Set RUN: YES/NO in Excel — no code knowledge needed
Test data changes between runs Hardcoded data in test files — fails when data changes Edit TEST_DATA column in Excel — smart merge preserves edits on every update
Viewing test results history Only the latest Playwright HTML report — previous runs lost Prism HTML report auto-generated after every run, dated archive kept in reports/

new:project
Scaffolds a complete new project. With --src, auto-detects the app framework (React Router, Next.js, Vue, Angular), scans all routes and dialog components, and generates page objects + test stubs + TODO_REPORT.md.
npm run new:project -- --name myapp --src D:\myapp
✓ Built
update:testbook
Smart-merges test case definitions into the project Excel workbook. Adds new rows, preserves user-edited TEST_DATA / RUN / NOTES columns, and flags removed tests [OBSOLETE]. Never overwrites user data.
npm run update:testbook -- --project myapp
✓ Built
heal:selectors
Navigates every page route using a role session, extracts the real h1/h2 heading from the live DOM, and patches expectLoaded() selectors automatically. Detects auth-redirect and permission-denied pages.
npm run heal:selectors -- --project myapp [--role admin] [--module settings]
✓ Built
heal:actions
Extracts all visible buttons, tabs, radio buttons, and input placeholders from each live page. Fuzzy-matches against action method selectors, auto-corrects role type (e.g. button→radio for Radix ToggleGroup).
npm run heal:actions -- --project myapp [--role receptionist]
✓ Built
heal:dialogs
Auto-detects dialog triggers from test files, navigates to parent page, opens each dialog, and extracts live placeholders + button labels. Patches getByLabel→getByPlaceholder and adds .first() to button clicks.
npm run heal:dialogs -- --project myapp [--dialog PatientDialog]
✓ Built
generate:report
Reads Playwright JSON output after a test run, enriches with Excel metadata (module, screen, role), and generates a dated Prism HTML report. Auto-runs via posttest hook — no manual step needed.
npm run generate:report -- --project myapp [--open]
✓ Built
setup-test-users
Enables email/password login for existing Supabase users without creating new accounts. Uses each user's email as their password. Run after every db:reset.
node scripts/setup-test-users.mjs
✓ Built
Prism — The Design System

Prism is DeepTree's HTML document format — a Playwright-inspired dark/light design system used for all ADAPT outputs: test reports, architecture docs, summaries, and dashboards. The name reflects how it refracts raw data into clear, organised views.

AssetLocationPurpose
playwright-theme.csscore/assets/playwright-theme.cssAll design tokens, components, dark + light CSS. Link or inline in any HTML.
report-template.htmlcore/assets/report-template.htmlBlank Prism shell — sidebar, topbar, theme toggle pre-wired. Copy and add sections.
html-builder.mjsscripts/lib/html-builder.mjsJS functions for programmatic HTML generation: getBaseHtml(), createSection(), createTable(), createPill(), createKpiGrid(), createRunTimeline(), createScriptList().

Link CSS
For pages inside the adapt/ repo — link the shared CSS file.
<link rel="stylesheet" href="../../core/assets/playwright-theme.css">
Inline CSS
For portable, self-contained single-file HTML (e.g. emailed reports).
import { getInlineCss } from './scripts/lib/html-builder.mjs';
Programmatic
Generate full reports from data using the builder functions.
const html = getBaseHtml({ title, sidebarStats, content: [ createSection(...) ] });

Existing App Guide

For an application that already exists and has running code. ADAPT plugs in non-invasively — no changes to the app's source code.

Plug & Play

ADAPT is designed as a platform, not a per-project tool. The monorepo structure means every new application adds a folder and inherits the full framework.

What's Shared (core/)What's Per-Project (projects/name/)

Slack reporterglobal-setup.ts (cleanup + Run ID)

Run ID generator + cleanup enginedata/*.xlsx (testbook — 4 standard sheets)
Base Playwright configpages/ (Page Object Model)
Prism design system (CSS + builder)tests/ (E2E test files)
All heal scriptsreports/ (auto-generated HTML)

# Adding a second project takes under 5 minutes:
npm run new:project -- --name onlinebooking --src D:\onlinebooking
# → Detects React Router, scans 20 routes, generates 20 page objects, creates Excel

npm run heal:selectors -- --project onlinebooking
# → Navigates each page, heals headings automatically

npm run test:onlinebooking
# → Full suite runs, Prism report generated at projects/onlinebooking/reports/
Every project added to ADAPT gets: heal scripts, Prism reports, Excel run control, multi-role auth, Slack notifications, and CI workflows — for free. Zero setup beyond the project folder itself.
Conventions & AI Enforcement

Enforced automatically by CLAUDE.md when the ADAPT repo is open in Claude Code. Every AI session follows these conventions without being reminded.

ConventionRuleWhy
Page objectsExtend BasePage, always have goto(), expectLoaded(), expectAccessDenied()Consistent interface across all pages
Dialog classesDo NOT extend BasePage. Always have expectOpen(), typed fill(data) with interface, action method, cancel()Dialogs are scoped, not pages
Dialog scopeAll interactions scoped to getByRole('dialog') to prevent selector conflictsAvoids multiple-match strict mode errors
SelectorsUse getByRole, getByLabel, getByPlaceholder — never CSS class selectorsResilient to styling changes
shadcn labelsgetByPlaceholder() preferred over getByLabel() inside shadcn dialogsshadcn FormLabel htmlFor is unreliable
Test IDsMODULE-E2E-001 format. RBA checks: RBA-MODULE-001Consistent, searchable, matches Excel
storageStateFile named after role lowercased: .auth/accountant.jsonConvention enforced by CLAUDE.md
Compliance reportAfter every creation task, Claude produces a compliance table (followed / missed / assumptions)Catches issues before tests run
